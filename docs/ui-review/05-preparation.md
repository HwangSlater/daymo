# 5단계 · 준비

## 목표

준비물이 많아져도 남은 일과 담당을 빠르게 파악하고, 개인 준비물과 공용 준비물의 완료 상태를 서로 혼동하지 않게 한다.

## 반영한 내용

- 완료 상태를 준비물 이름이 아닌 고유 ID로 관리한다.
- 같은 이름의 준비물을 서로 다른 멤버가 가지고 있어도 각각 따로 완료할 수 있다.
- 같은 담당자에게 같은 이름의 준비물을 다시 추가하는 중복은 제외한다.
- 담당을 바꿀 때 해당 멤버의 목록에 같은 준비물이 있으면 이동하지 않고 안내한다.
- 여러 준비물을 한 번에 입력할 때 입력 목록 내부의 중복도 제외한다.
- 상태·담당·태그 필터를 함께 적용한 개수를 담당 버튼에 표시한다.
- 완료 보기에서는 담당별 완료 개수, 남은 준비 보기에서는 담당별 남은 개수를 표시한다.
- 준비물 담당 버튼에서 담당 변경과 정보 수정으로 이어지는 관리 화면을 제공한다.
- 준비물 이름, 수량, 담당, 태그를 수정하거나 해당 항목을 삭제할 수 있다.
- 태그는 현재 준비물에서 사용 중인 값만 보여 주며 마지막 사용 항목이 사라지면 필터를 초기화한다.
- 목록 붙여넣기에서 담당자와 이름 조합이 같은 준비물을 중복 반영하지 않는다.
- 체크 동작의 접근성 문구를 현재 상태에 따라 `완료` 또는 `완료 해제`로 구분한다.
- 상태·담당·태그·담당 지정 선택에 접근성 역할과 선택 상태를 추가했다.

## 완료 기준

- `하늘`, `여울`: 해당 멤버의 개인 준비물이며 각자 완료한다.
- `공용`: 둘 중 한 명이 챙기면 함께 확인하는 하나의 항목이다.
- `미정`: 담당을 정하기 전의 항목이며 완료할 수는 있지만 담당 지정이 우선이다.
- 같은 물건이 개인별로 필요하면 담당자를 다르게 해 별도 항목으로 둔다.

## 화면 원칙

- 전체 진행률은 현재 목록의 고유 준비물 개수를 기준으로 계산한다.
- 기본 화면에서는 완료 항목을 접어 남은 준비에 집중한다.
- 첫 번째 태그를 묶음 기준으로 사용하고 묶음은 접고 펼칠 수 있다.
- 담당 변경과 항목 수정은 체크 동작과 분리해 실수로 완료 상태가 바뀌지 않게 한다.

## 개발 단계로 넘기는 항목

- 완료한 사용자와 완료 시각 기록
- 멤버 추가·삭제에 따른 담당자 마이그레이션
- 실시간 동시 체크와 충돌 처리
- 목록 교체 시 서버에서 삭제·추가 차이를 계산하는 동기화
- 반복 여행에서 자주 쓰는 준비물 템플릿
