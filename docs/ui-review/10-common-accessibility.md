# 10단계 · 앱 공통 UI와 접근성

## 범위

- 홈, 여행 목록, 여행 상세, 장소, 준비, 요리, 기록, 찾기, 우리의 글자 체계
- 공통 섹션 동작, 더 보기, 하단 탭의 접근성 정보와 터치 영역
- iOS 안전 영역과 시스템 글자 크기 변화
- 추가·수정·삭제 화면의 공통 표현

## 검토 결과

### 글자 크기

- 화면 제목은 18pt 이상, 기본 본문과 입력값은 13~17pt, 보조 정보는 11~12pt로 계층이 유지된다.
- 11pt 문구의 대부분은 날짜, 개수, 태그, 보조 설명이므로 일괄 확대하지 않았다. 한 화면에 많은 정보를 보여주는 Daymo의 밀도를 유지하기 위한 결정이다.
- 실제 조작에 쓰이면서 9pt였던 지도 초기화, 검색 개수, 멤버 역할은 10pt 이상으로 올렸다.
- 계정 삭제 문구는 11pt로, 교통편 출발·도착 입력값은 13pt로 올렸다.
- 빈 상태 설명의 줄 간격을 넓혀 두 줄 이상에서도 읽기 쉽게 했다.

### 접근성과 터치

- 섹션 우측 동작과 목록 더 보기/접기 버튼에 버튼 역할과 읽기 이름을 추가했다.
- 더 보기/접기에는 펼침 상태를 전달한다.
- 작은 텍스트 동작은 화면 밀도를 늘리지 않도록 시각 크기 대신 `hitSlop`으로 터치 영역을 보완했다.
- 하단 탭은 탭 역할, 이름, 선택 상태를 유지한다.

### 안전 영역

- React Native의 폐기 예정 `SafeAreaView` 대신 `react-native-safe-area-context`를 사용한다.
- 앱 루트에 `SafeAreaProvider`와 초기 화면 치수를 연결해 첫 화면부터 상태 표시줄과 콘텐츠가 겹치지 않게 했다.
- iOS 네이티브 빌드를 갱신해 `RNSafeAreaView`가 실제 앱에 포함되는 것을 확인했다.

## 시스템 글자 크기 검수

- iOS 기본 크기와 큰 글자 크기에서 홈 화면의 제목, 여행 카드, 바로가기, 체크리스트, 하단 탭이 읽히고 주요 문구가 잘리지 않는 것을 확인했다.
- 접근성 최대 크기에서는 큰 장식 제목과 3분할 여행 바로가기가 여러 줄로 바뀌어 현재 고정 카드 구조에 맞지 않는다.
- 임의로 시스템 글자 확대를 제한하면 접근성을 떨어뜨리므로 `maxFontSizeMultiplier`로 숨기지 않았다. 출시 전 접근성 고도화 단계에서 최대 크기일 때 여행 카드와 바로가기를 세로형으로 전환하는 반응형 레이아웃이 필요하다.
