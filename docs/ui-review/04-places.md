# 4단계 · 장소

## 목표

여행 전에 모아 둔 장소를 빠르게 훑고, 후보·일정·대표 숙소 중 현재 상태를 혼동 없이 관리할 수 있게 한다.

## 반영한 내용

- 상태 필터를 `전체`, `저장`, `일정`, `대표 숙소`로 구분했다.
- 대표 숙소 카드는 상태 배지와 동작 문구에서도 대표 숙소임을 명확히 표시한다.
- 일정에 담은 장소는 같은 화면에서 다시 추가할 수 없고 버튼에도 현재 상태를 표시한다.
- 일정에 담을 때 선택하는 날짜를 실제 여행 기간과 연결하고 선택 날짜를 일정 데이터에 보존한다.
- 장소마다 고유 ID를 사용해 이름이 바뀌어도 수정·삭제 대상을 안정적으로 구분한다.
- 같은 이름의 장소가 중복 저장되지 않도록 완료 버튼에서 즉시 안내한다.
- 대표 숙소를 수정하면 여행 정보에도 이름과 주소를 반영하고, 삭제하거나 종류를 바꾸면 대표 숙소 상태도 해제한다.
- 태그는 장소 데이터에서 실시간으로 구성하며 마지막 사용 장소가 사라지면 필터도 자동으로 해제한다.
- 현재 UI 시안의 목록 복사·붙여넣기는 개발 우선순위 결정에서 출시 후 최종 후순위로 이동했다.
- 초기 개발에서는 단일 네이버 지도 공유 텍스트 자동 채우기만 유지한다.
- 상태·태그·일정 추가 버튼에 선택 및 비활성 접근성 상태를 추가했다.

## 화면 원칙

- `저장`은 아직 일정에 넣지 않은 후보, `일정`은 날짜와 시간을 정한 장소를 뜻한다.
- 대표 숙소는 장소의 종류가 아니라 이번 여행에서 맡은 역할로 별도 표시한다.
- 태그는 별도 관리 화면을 만들지 않고 실제 장소에서 사용 중인 값만 노출한다.
- 검색과 필터 결과가 없을 때 한 번에 조건을 초기화할 수 있어야 한다.

## 개발 단계로 넘기는 항목

- 장소와 일정 사이의 고유 ID 연결 및 일정 삭제 시 상태 동기화
- 여러 숙소와 숙박 기간을 지원하는 데이터 모델
- 네이버 지도 단축 링크의 서버 또는 앱 링크 메타데이터 해석
- 비슷한 이름·주소·지도 링크를 이용한 중복 장소 추천
- 공동 편집 중 삭제·수정 충돌 처리

## 검수 결과

- TypeScript 타입 검사 통과
- 코드 공백 및 충돌 검사 통과
- iOS 시뮬레이터에서 필터 4개, 검색, 태그, 대표 숙소와 일정 상태의 배치를 확인
