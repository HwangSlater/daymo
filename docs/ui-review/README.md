# Daymo UI 단계별 개선 계획

이 문서는 현재 UI 검토 결과를 탭 단위 작업으로 나누고 진행 상태를 기록한다.
백엔드와 동기화 구현 전까지는 화면 구조, 사용자 동선, 상태 표현, 문구와 접근성을 우선한다.

## 작업 원칙

- 한 단계는 하나의 탭 또는 하나의 공통 UX 주제로 묶는다.
- 각 단계 시작 전 범위와 제외 항목을 확인한다.
- 완료 후 타입 검사와 iOS 시뮬레이터를 검수한다.
- 단계별로 독립 커밋을 남겨 되돌릴 수 있게 한다.
- 완료할 때 다음 진행 순서를 다시 안내한다.

## 진행 순서

| 단계 | 범위 | 핵심 목표 | 상태 |
| --- | --- | --- | --- |
| 1 | 홈 | 다음 여행 기준, 빈 상태, 바로가기 의미 정리 | 완료 |
| 2 | 여행 목록·지도·캘린더 | 보기 간 필터와 선택 상태, 생성 후 동선 정리 | 완료 |
| 3 | 여행 상세·일정·교통·숙소 | 여행 기간 기반 입력과 여러 정보의 관계 정리 | 완료 |
| 4 | 장소 | 후보·일정·숙소 상태, 중복과 태그 관리 정리 | 완료 |
| 5 | 준비 | 담당·공용 완료 기준, 미정과 중복 관리 정리 | 완료 |
| 6 | 요리 | 여러 요리와 통합 장보기 목록의 흐름 정리 | 다음 |
| 7 | 기록 | 사진·일기·여행 카드의 빈 상태와 저장 흐름 정리 | 대기 |
| 8 | 찾기 | 검색 범위, 최근 검색 관리, 유형별 빠른 동작 정리 | 대기 |
| 9 | 우리·로그인·설정 | 공간·멤버·계정의 정보 구조와 권한 상태 정리 | 대기 |
| 10 | 앱 공통 | 추가·수정·삭제 패턴, 빈 상태, 접근성, 글자 확대 검수 | 대기 |

## 개발 단계로 넘기는 항목

- 여행 ID를 기준으로 일정·장소·준비·요리·기록 연결
- 로컬 저장과 서버 동기화
- 실시간 공동 편집과 충돌 처리
- 로그인 세션과 소셜 인증
- 권한별 서버 검증
- 사진 업로드와 기기 저장

단계별 상세 결정과 결과는 같은 폴더의 문서에 기록한다.
