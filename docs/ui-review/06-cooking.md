# 6단계 · 요리

## 목표

여러 요리의 재료를 메뉴별로 관리하면서도 여행 전체 장보기와 담당을 한눈에 확인하고, 필요한 재료를 준비물로 옮기는 흐름을 짧게 만든다.

## 반영한 내용

- 요리 탭 상단에 모든 메뉴를 합친 `통합 장보기` 요약을 제공한다.
- 통합 목록에서 `전체`, `하늘`, `여울`, `구매`, `미정`으로 재료를 필터링한다.
- 필터 결과는 요리별로 묶어 보여 주고 수량과 준비 방법을 함께 표시한다.
- 통합 장보기 완료 버튼을 누르면 준비 탭으로 이동하는 동시에 `요리 재료 불러오기` 화면을 연다.
- 준비물로 가져올 때 여러 요리에 같은 재료가 있으면 한 항목만 추가한다.
- `구매` 재료를 준비물로 가져오면 구매 태그를 보존하고 담당은 미정으로 둔다.
- 같은 요리 안에서 같은 이름의 재료가 중복 저장되지 않도록 막는다.
- 같은 이름의 요리도 중복 등록되지 않도록 막는다.
- 재료 목록 붙여넣기와 GPT 결과 가져오기에서 요리·재료 중복을 제외한다.
- 레시피 링크 형식을 확인하고 잘못된 링크는 저장하지 않는다.
- 재료가 없는 요리에 첫 재료 추가 빈 상태를 제공한다.
- 메뉴 선택, 통합 장보기, 레시피 링크, 재료 체크와 수정에 접근성 역할·상태·문구를 추가했다.

## 상태 기준

- `하늘`, `여울`: 해당 멤버가 미리 준비할 재료다.
- `구매`: 여행 전이나 현지에서 구입해야 하지만 아직 담당자는 정하지 않은 재료다.
- `미정`: 준비 방법과 담당을 아직 정하지 않은 재료다.
- 요리 탭의 체크는 재료 준비 여부이며, 준비 탭으로 가져온 항목의 체크와는 개발 단계에서 동기화한다.

## 화면 원칙

- 메뉴 카드는 현재 선택한 요리와 재료 수를 빠르게 비교하는 용도로 유지한다.
- 현재 요리에서는 분류별 재료 수정에 집중하고, 여러 요리 비교는 통합 장보기에서 처리한다.
- 동일한 재료라도 요리별 수량은 통합 목록에서 각각 보여 주되 준비물로 옮길 때는 중복 추가하지 않는다.
- 재료가 많아지면 준비 방법 필터와 요리별 묶음으로 탐색 범위를 줄인다.

## 개발 단계로 넘기는 항목

- 같은 재료의 수량 단위를 해석해 통합 수량으로 합산하는 규칙
- 요리 재료 체크와 준비물 완료 상태의 ID 기반 양방향 동기화
- 구매 장소·구매 시점과 담당 멤버를 분리하는 데이터 모델
- 외부 레시피 링크 미리보기와 앱 내 브라우저
- GPT 변환 결과의 서버 검증과 오류 행별 안내

## 검수 결과

- TypeScript 타입 검사 통과
- 코드 공백 및 충돌 검사 통과
