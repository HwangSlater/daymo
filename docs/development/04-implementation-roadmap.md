# 단계별 개발 계획

## 진행 원칙

- UI가 완성된 현재 상태를 기준선으로 고정하고 기능을 한 영역씩 실제 데이터로 교체한다.
- 각 단계는 별도 브랜치·커밋으로 진행하며 완료 시 시뮬레이터와 staging에서 보여준 뒤 다음 단계 승인을 받는다.
- 승인 전에는 다음 단계의 제품 결정을 임의로 확정하지 않는다.
- 각 단계의 종료 조건은 코드 작성 완료가 아니라 실제 저장·재접속·다른 계정 동기화까지다.

## 0단계 — 개발 기준선과 결정 확정 (2~3일)

작업:

- 현재 UI 화면/폼/버튼 목록을 회귀 체크리스트로 고정
- ConoHa VPS OS/도메인/방화벽과 Docker 운영 기준 확인
- Java 21, Spring Boot, PostgreSQL 버전 확정
- 확정된 VPS private 사진 volume과 Google Drive 암호화 백업 경로 검증
- 앱 bundle identifier와 Android package name 확정
- 개인정보 처리방침/이용약관 초안 위치 결정
- 개인정보 처리자/보호책임자 연락처와 사업자 표시 정보 확정
- ConoHa, Google Drive, Sentry, OAuth 사업자의 실제 처리 국가·위탁/국외 이전 항목 확인
- dev/staging/prod 프로젝트와 secret 관리 방식 생성
- 공개 가입에 필요한 이메일 소유 확인, 가입·로그인 rate limit, 자동 가입 방어와 문의 경로 설계
- [`10-implementation-readiness.md`](./10-implementation-readiness.md)의 D-001~D-004 결정
- Node LTS/JDK 21 설치, `.nvmrc`·`engines`·앱 식별자 고정
- npm audit 경고를 별도 Expo SDK 호환 브랜치에서 검증
- 현재 모든 UI 동작을 [`09-ui-development-traceability.md`](./09-ui-development-traceability.md)로 회귀 고정

확정된 기반 정책:

1. Google Drive 백업은 Daymo 전용 Google 계정 사용
2. 공개 회원가입, 공간 콘텐츠는 초대 멤버 전용
3. owner/editor의 타인 메모 삭제 허용과 감사 로그 유지
4. 만 14세 이상만 가입, 생년월일 원본 미수집

완료 기준: 개발자가 새 PC에서 문서만 보고 iOS/Android/local backend를 실행할 수 있다.

## 1단계 — 앱 구조와 기반 공사 (3~5일)

- Expo Router 도입, 현재 2개 대형 파일을 route/feature 단위로 점진 분리
- QueryClient, typed REST client, SecureStore session, 환경 설정 구성
- SQLite local store, 동기화 cursor, 파일 캐시와 네트워크 상태 계층 구성
- Spring Boot 모듈, PostgreSQL/Flyway, OpenAPI, Testcontainers 구성
- 공통 API 오류/로딩/재시도/토스트 처리
- theme token과 기존 UI 회귀 테스트
- CI에 typecheck, test, Expo export 추가
- SQLite snapshot·SecureStore·outbox를 최소 spike로 먼저 검증
- OpenAPI 생성 타입을 앱 typed client의 단일 계약으로 고정

완료 기준: 더미 repository와 실제 repository를 바꿔 끼울 수 있고 기존 화면/딥링크가 동일하게 동작한다. 네트워크를 끊고 재실행해도 마지막 홈과 여행을 즉시 볼 수 있다.

## 2단계 — 인증과 프로필 (4~7일)

- 이메일 회원가입·로그인·로그아웃·30분 1회용 링크 기반 비밀번호 재설정과 전체 세션 폐기
- 30분·1회용 링크 기반 가입 이메일 인증, Universal/App Link와 웹 fallback, 인증 재전송·만료 처리
- IP·계정·기기 기준 가입/로그인 rate limit과 반복 실패 방어
- 기기별 로그인 session 조회·폐기
- Apple·Google·Kakao·Naver 서버 OAuth를 첫 출시 범위로 구현
- 프로필 이름/사진, 세션 자동 복원
- 탈퇴와 토큰 폐기
- 약관/처리방침 version 조회, 필수 확인·선택 동의·철회 이력
- 앱 내 계정 삭제와 웹 삭제 요청 경로
- 개인정보 열람·정정·삭제·처리정지 요청 접수
- 내 계정·동의·참여 이력·본인 작성 콘텐츠·본인 사진 원본의 비동기 export와 24시간 1회용 다운로드
- 현재 자동 로그인 더미 제거

검증: 앱 재실행 자동 로그인, 만료 토큰 갱신, 네 OAuth 제공자의 취소/실패·계정 연결 해제, 동일 이메일 계정 병합, 다른 계정 전환, 선택 동의 거부/철회, 계정 삭제, 구 문서 version 증빙.

승인 체크포인트: 로그인/회원가입 실제 동작과 오류 문구를 시연한 뒤 공간 개발로 이동.

## 3단계 — 우리 공간과 멤버 (5~7일)

- spaces, memberships, invites, relationship profile Flyway migration과 서비스 권한 검증
- 공간 생성, 초대 링크, 참여, 공간 전환
- 공간 나가기 전 본인 사진 검토, 공동 콘텐츠 유지와 로컬 공간 데이터 제거
- 멤버 내보내기 시 공동 콘텐츠 유지, 접근·pending mutation 즉시 차단
- 앱 내 사용자·콘텐츠 신고, 사용자 차단과 기존 공동 공간의 나가기/내보내기 안내
- 신고 즉시 접수·24시간 최초 검토 queue, 긴급 콘텐츠 임시 제한과 운영 기한 경고
- versioned 금지 문구·위험 URL 필터와 오탐 관리; 초기 사진 외부 자동 판별은 제외
- 일반 앱과 분리된 관리자 웹, allowlist 관리자·필수 MFA·moderation 감사 로그
- 관리자 TOTP 등록·로그인, 10개 일회용 복구 코드와 분실 복구 운영 절차
- 신고 결과 14일 이의 제기, 신고 1년·관리자 감사 로그 2년 보존과 자동 파기
- 긴급 신고 즉시 알림·일반 신고 1시간 요약과 민감정보 없는 운영 알림 template
- 멤버별 담당 선택에 실제 membership 연결
- 멤버 내보내기 확인창과 권한
- 테마/다크모드/마지막 공간은 기기에 저장하고 membership은 서버에서 검증
- 서비스 알림 설정과 마케팅 동의를 분리하고 push token 생명주기 연결
- 잠금화면 상세정보 없는 push payload와 기기별 opt-in 생체 앱 잠금
- 백그라운드 1분 잠금, OS 기기 암호 fallback, app switcher privacy cover와 스크린샷 허용

검증: 서로 다른 두 계정, 친구 4명 공간, 권한 없는 공간 접근 차단.

## 4단계 — 여행 기반과 홈 (5~8일)

- 여행 CRUD, 날짜 범위와 자동 trip days
- 목록·지도·캘린더가 같은 API 데이터를 사용
- 지역 선택 UX와 region code 저장
- 홈 dashboard 집계와 빠른 이동
- 수동 여행 보관·보관 해제, 보관함에서만 가능한 여행 삭제와 7일 휴지통 복구
- 지난 여행의 여행·장소·요리 편집 확인과 기기별 10분 재확인 유예; 준비·기록·사진은 제외
- 홈의 지난 여행 기록 카드와 정확한 기록 탭 이동
- 시작 캐시로 홈 즉시 표시
- ETag와 sync cursor로 변경분만 내려받고 삭제 tombstone 반영

검증: 월 경계/윤년/같은 날 여행, 지역 필터, 100개 여행 pagination, 오프라인 재실행, 304 응답, 증분 동기화.

승인 체크포인트: 여행 생성→홈→목록/지도/캘린더→상세 진입 전 흐름 확인.

## 5단계 — 여행 일정과 여행 정보 (7~10일)

- 날짜별 일정 CRUD/정렬/전체 보기
- 숙소 등록과 편한 체크인·체크아웃 선택
- 예약 정보 CRUD
- 가는 편/오는 편 교통 CRUD와 후속 입력 제안
- 여행 메모 CRUD, 작성자/수정 시각/삭제 권한
- SSE와 재조회로 두 기기 갱신
- 안전한 행동은 pending mutation으로 보관하고 재연결 시 idempotent 전송

검증: 시간대, 날짜 변경, 버전 충돌, 상대가 삭제/수정한 데이터 반영.

## 6단계 — 장소와 태그 (6~9일)

- 장소 CRUD, 상태/태그/검색 필터
- 네이버·카카오 지도 공유 텍스트는 기기에서 자동 입력하고 필요할 때만 서버로 단축 URL 확인
- 외부 지도 링크 열기와 잘못된 URL 처리
- 장소를 일정에 담기
- `숙소` 분류 장소만 숙소로 등록
- 사용되지 않는 태그 정리

검증: 한글 주소, 단축 URL, 태그 30개, 장소 200개, 중복 장소 경고.

## 7단계 — 준비물과 공동 체크 (6~9일)

- 개인/멤버/공용 담당과 남음/완료 필터
- 태그, 접기, 진행률, 많은 목록 pagination/가상화
- 항목 전체 영역 체크, 낙관적 업데이트
- 담당 변경 선택창과 완료자 기록
- 복사/붙여넣기 일괄 수정, 중복 후보 경고

검증: 두 기기 동시 체크, 담당자 탈퇴, 300개 준비물, 실패 시 UI rollback.

승인 체크포인트: 실제 다음 여행 준비물을 두 계정이 함께 체크해 본 뒤 요리로 이동.

## 8단계 — 요리와 재료 (6~9일)

- 요리 여러 개 CRUD, source URL/YouTube 외부 열기
- 재료 CRUD, 사용자 분류 태그, 준비/구매 구분과 담당
- 내가 준비할 재료 모아보기
- 선택 재료를 준비물로 가져오기
- 고정 형식 복사 프롬프트와 여러 요리 붙여넣기 미리보기
- 주방 없는 여행에서 요리 탭 숨김 설정

검증: 요리 30개/재료 500개, 동일 재료, 잘못된 가져오기 형식, 준비물 출처 연결.

## 9단계 — 사진·일기·회고 (8~12일)

- 카메라/앨범 권한과 다중 선택
- 원본 VPS stream 업로드, 표시본·썸네일 생성, 재시도
- 기본 전체 네트워크 원본 업로드, 기기별 Wi-Fi 전용 옵션, 영속 대기열·자동 재개와 LRU 파일 캐시
- 여행/날짜/장소/일정/숙소에 사진 연결
- 여행 일기 CRUD와 draft 보존
- 여행 통계와 사진 회고 카드의 최소 버전
- 업로더 본인 사진과 owner 전체 사진의 삭제·7일 복구 권한
- 업로더 본인 사진과 owner 전체 사진의 설명·날짜·장소·일정 연결 수정 권한
- 80% 사전 경고와 여행별·큰 사진별 저장 공간 관리, 한도 도달 시 신규 업로드만 차단

원본 보관과 한도는 사진당 20MB, 공간당 1GB, 서버 전체 30GB로 확정했으며 초기 동영상은 지원하지 않는다.

## 10단계 — 찾기와 데이터 이관 (5~8일)

- 여행·일정·장소·준비·요리·메모 통합 검색
- 검색 결과에서 정확한 상세 탭으로 이동
- 최근 검색/빈 상태
- 기존 카카오톡 원문을 보존하는 가져오기 도구
- 실제 원문 시드로 누락된 모델 재검토

검증: 부분 한글, 띄어쓰기, 삭제 데이터 제외, 다른 공간 결과 차단.

## 11단계 — 출시 안정화 (7~14일)

- 접근성 라벨, 글자 확대, 색 대비, 키보드/스크린리더
- 저속 네트워크, 재시도, 빈 상태, 권한 거부 전체 점검
- 앱 시작/홈/대형 목록/이미지 성능 측정
- API 권한/IDOR 보안 테스트, rate limit, 백업/복원 훈련
- Sentry, 운영 로그, 알림, 상태 대시보드
- 제3자 행동 분석 SDK 없이 출시하고 Sentry는 30일·가명 설치 ID·오류 진단 최소 정보·PII scrubbing만 사용
- TestFlight/Android 내부 테스트와 실제 여행 파일럿
- 스토어 설명, 개인정보 처리방침, 계정 삭제 경로
- App Store Privacy와 Google Play Data safety 실제 처리 현황 대조
- 개인정보 유출 대응 연락망과 통지/신고 모의훈련

완료 기준: 두 명 이상이 카카오톡 공지 없이 여행 하나를 생성·준비·기록·회고할 수 있고 치명적 데이터 손실이 없다.

## 출시 후 최종 후순위

- 장소 목록 복사·붙여넣기, 외부 편집, 추가/교체 미리보기와 일괄 transaction

네이버·카카오 지도에서 장소 하나를 공유한 텍스트로 추가 화면을 자동 채우는 기능은 초기 범위에 유지한다. 여기서 미루는 범위는 여러 장소 목록의 일괄 복사·붙여넣기뿐이다.

## 예상 일정

한 명이 UI 검토와 병행하면 MVP는 약 12~18주다. OAuth·스토어 심사·사진 처리와 실제 공동 사용 피드백에 따라 달라진다. 빠른 검증을 위해 4단계까지를 첫 수직 슬라이스, 7단계까지를 실제 계획용 알파, 11단계를 공개 가능한 MVP로 본다.

## 각 단계 보고 형식

매 단계 종료 시 다음을 제공한다.

- 구현된 사용자 흐름과 제외된 범위
- 시뮬레이터/실기기 확인 결과
- DB migration과 API 변경 목록
- 자동/수동 테스트 결과
- 성능 또는 보안 위험
- 해당 단계로 되돌릴 수 있는 Git 커밋/태그
- 다음 단계에서 사용자의 승인이 필요한 결정
