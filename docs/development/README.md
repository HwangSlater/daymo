## 문서 상태

- 기준 UI: `main` 브랜치 `164905d` 이후 UI를 기준으로 하며 개발 시작 시 태그로 고정
- 앱 버전: `0.1.0`
- 마지막 개발 준비 감사: 2026-08-14
- 현재 상태: 이메일 인증, 공간·여행 조회·생성·수정, 공간 멤버 표시, 계정 삭제가 API에 연결됐다. 여행 상세 기록은 아직 기기에 남으며 참가자·하위 데이터 API와 출시 준비가 다음 단계다. 자세한 것은 아래 [현재 위치](#현재-위치).
- 목표: UI를 유지하면서 실제 인증, 공동 공간, 여행 데이터, 파일 저장과 동기화를 순차 연결한다.
- 백엔드 기준: Python 3.13 + FastAPI, iwinv VPS(2vCPU/2GB RAM/50GB NVMe/일 20GB·월 600GB 트래픽)

**다음 시작점은 2번이다.** 이제 앱의 멤버가 서버 membership id를 들고 있어서
(`Member.id`) 참가자를 이름이 아니라 id로 저장할 수 있다.

1번을 하며 남긴 것:

- **내 이름·이메일 고치기가 아직 기기에만 저장된다.** 서버에 `PATCH /me` 가 없다.
  "우리" 탭 계정 칸에서 고쳐도 다시 로그인하면 서버 값으로 돌아간다

  공간에는 여행처럼 `version` 이 없다. 관리자만 고칠 수 있어 부딪힐 일이 드물다고 봤다

## 제품 원칙

- 앱을 열고 다음 여행을 확인하는 데 네트워크 때문에 오래 기다리지 않게 한다.
- 여행을 중심으로 일정, 장소, 준비, 요리, 기록을 구조화한다.
- 연인과 친구 공간은 같은 여행 기능을 쓰고 관계별 표현만 달리한다.
- 공동 편집에서 누가 담당하고 무엇이 완료됐는지 즉시 알 수 있어야 한다.
- 네이버·카카오 지도 링크는 지원하되 특정 제공자 링크를 필수 입력으로 만들지 않는다.
- 서버 연동 중에도 현재 UI의 빠른 반응을 유지하도록 낙관적 업데이트와 로컬 캐시를 사용한다.

## 우선순위 표기

- `P0`: 앱 출시와 데이터 안전에 필수
- `P1`: 현재 UI를 실제 기능으로 완성하는 범위
- `P2`: 출시 후 확장
- `결정 필요`: 구현 전에 사용자 승인을 받아야 하는 제품 또는 인프라 선택
