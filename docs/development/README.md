# Daymo 개발 문서

이 폴더는 현재 UI 프로토타입을 실제 iOS·Android 서비스로 전환하기 위한 기준 문서다. 기존 요구사항은 `../01-requirements.md`, 실제 사용 예시는 `../02-raw-travel-data.md`를 원문으로 유지한다.

2. [시스템·데이터 설계](./02-architecture-and-data-model.md): 앱 구조, 도메인, 권한, 동기화
3. [API 명세](./03-api-specification.md): 화면별 API와 요청·응답 계약
4. [단계별 개발 계획](./04-implementation-roadmap.md): 구현 순서, 완료 기준, 승인 지점
5. [품질·운영 기준](./05-quality-and-operations.md): 테스트, 성능, 보안, 모니터링
6. [ConoHa VPS 운영](./06-conoha-vps-deployment.md): 2GB 서버 구성, 배포, 백업과 용량 정책
7. [기기 저장·동기화](./07-local-first-and-sync.md): 로컬/서버 책임, 증분 동기화, 데이터 절약
8. [개인정보·출시 준수](./08-privacy-and-release-compliance.md): 동의, 처리방침, 권한, 탈퇴, 스토어 신고
9. [UI-개발 추적표](./09-ui-development-traceability.md): 현재 화면별 데이터·API·로컬 처리·테스트 연결

## 문서 상태

- 기준 UI: `main` 브랜치 `164905d` 이후 UI를 기준으로 하며 개발 시작 시 태그로 고정
- 앱 버전: `0.1.0`
- 마지막 개발 준비 감사: 2026-08-14
- 현재 상태: UI 프로토타입. 화면 데이터와 인증은 대부분 로컬 상태/더미 데이터다.
- 목표: UI를 유지하면서 실제 인증, 공동 공간, 여행 데이터, 파일 저장과 동기화를 순차 연결한다.
- 백엔드 기준: Java 21 + Spring Boot 3.x, ConoHa VPS(3Core/2GB RAM/SSD 100GB/트래픽 무제한)

## 제품 원칙

- 앱을 열고 다음 여행을 확인하는 데 네트워크 때문에 오래 기다리지 않게 한다.
- 여행을 중심으로 일정, 장소, 준비, 요리, 기록을 구조화한다.
- 연인과 친구 공간은 같은 여행 기능을 쓰고 관계별 표현만 달리한다.
- 공동 편집에서 누가 담당하고 무엇이 완료됐는지 즉시 알 수 있어야 한다.
- 네이버·카카오 지도 링크는 지원하되 특정 제공자 링크를 필수 입력으로 만들지 않는다.
- 서버 연동 중에도 현재 UI의 빠른 반응을 유지하도록 낙관적 업데이트와 로컬 캐시를 사용한다.

## 우선순위 표기

- `P0`: 앱 출시와 데이터 안전에 필수
- `P1`: 현재 UI를 실제 기능으로 완성하는 범위
- `P2`: 출시 후 확장
- `결정 필요`: 구현 전에 사용자 승인을 받아야 하는 제품 또는 인프라 선택

## 현재 착수 판정

- 문서 설계: 개발 0단계 착수 가능
- 앱 기능 구현: [`10-implementation-readiness.md`](./10-implementation-readiness.md)의 P0 결정과 로컬 환경 게이트 완료 후 시작
- 운영 배포: 개인정보·외부 서비스·도메인·백업 결정 전까지 금지
