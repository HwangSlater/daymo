## 문서 상태

- 기준 UI: `main` 브랜치 `164905d` 이후 UI를 기준으로 하며 개발 시작 시 태그로 고정
- 앱 버전: `0.1.0`
- 마지막 개발 준비 감사: 2026-08-14
- 현재 상태: 이메일 인증과 공간·여행 조회·생성·수정이 운영 API에 연결됐다. 여행 상세 기록은 아직 기기에 남으며 공간 멤버 표시와 하위 데이터 API가 다음 단계다. 자세한 것은 아래 [현재 위치](#현재-위치).
- 목표: UI를 유지하면서 실제 인증, 공동 공간, 여행 데이터, 파일 저장과 동기화를 순차 연결한다.
- 백엔드 기준: Python 3.13 + FastAPI, iwinv VPS(2vCPU/2GB RAM/50GB NVMe/일 20GB·월 600GB 트래픽)

### 다음에 할 일

1. **공간 정보를 앱에 연결한다.** `/spaces/{id}/members`로 실제 멤버와 권한을
   표시하고, 공간 이름·관계·함께한 시작일 변경을 `/spaces/{id}`에 저장한다.
   초대 API가 생기기 전까지 임의 이름으로 멤버를 추가하는 현재 UI는 막는다.
2. **여행 참가자를 서버에 연결한다.** 여행 생성·수정 화면의 참가자를 membership
   ID로 저장하고, 다른 기기에서 바뀐 version과 충돌하면 최신 내용을 다시 보여 준다.
3. **여행 하위 데이터 API를 만든다.** `장소 → 일정·숙소 → 비용 → 준비·요리 → 기록`
   순으로 연결한다. 표는 이미 있고 API가 아직 없다.
4. **로컬 우선 동기화를 완성한다.** 하위 기록을 SQLite에 저장하고 outbox·증분 sync로
   오프라인 작성, 재시도, 공동 편집 충돌을 처리한다.
5. **출시 준비를 마친다.** 권한 문구·개인정보 처리방침·계정 삭제를 실기기에서 점검하고,
   iPhone·Android 스크린샷과 스토어 메타데이터를 새 UI로 다시 만든 뒤 TestFlight와
   Play 내부 테스트를 통과시킨다.

**다음 시작점은 1번이다.** 공간 설정과 실제 멤버가 일치해야 참가자와 담당자 ID를
안전하게 연결할 수 있다.

### 막혀 있는 것 — 바깥 자격증명이 있어야 한다

- **실제 메일 발송.** SMTP 전송 코드는 배포됐다. Resend API 키를 VPS의
  `SMTP_PASSWORD`에 넣고 발신 도메인을 인증해야 가입 확인 메일이 실제로 간다
- **OAuth.** Google·Apple·Kakao·Naver 사업자 등록과 키가 필요하다. 키 없이도
  흐름(일회용 앱 로그인 코드 → 교환)은 만들 수 있다
- **bot challenge.** 검증 공급자를 문서가 일부러 미뤄 뒀다(처리 국가·SDK·비용
  재승인 필요). 지금은 시도 제한이 그 자리를 막고 있다
- **외부 백업.** VPS 로컬 DB 스냅샷과 복원 검사는 동작한다. Google Drive용
  restic·rclone 구성은 준비됐고 OAuth 연결 후 타이머를 켜고 실제 복원을 확인해야 한다

### 앱 쪽에 남은 것

- 스크린샷 8장이 낡았다. 비용 탭이 없던 시절 화면이다. orca 로 찍으려면
  캡처가 창 포커스를 요구하고 뷰포트가 971x575라 기존 426x880을 맞출 수 없다.
  실기기나 시뮬레이터로 찍는 편이 낫다

## 제품 원칙

- 앱을 열고 다음 여행을 확인하는 데 네트워크 때문에 오래 기다리지 않게 한다.
- 여행을 중심으로 일정, 장소, 준비, 요리, 기록을 구조화한다.
- 연인과 친구 공간은 같은 여행 기능을 쓰고 관계별 표현만 달리한다.
- 공동 편집에서 누가 담당하고 무엇이 완료됐는지 즉시 알 수 있어야 한다.
- 네이버·카카오 지도 링크는 지원하되 특정 제공자 링크를 필수 입력으로 만들지 않는다.
- 서버 연동 중에도 현재 UI의 빠른 반응을 유지하도록 낙관적 업데이트와 로컬 캐시를 사용한다.

## 우선순위 표기

- `P0`: 앱 출시와 데이터 안전에 필수
- `P1`: 현재 UI를 실제 기능으로 완성하는 범위
- `P2`: 출시 후 확장
- `결정 필요`: 구현 전에 사용자 승인을 받아야 하는 제품 또는 인프라 선택
