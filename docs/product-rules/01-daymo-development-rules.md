# 현재 Daymo 개발 규칙

## 1. 작업과 의사결정

- UI 검토를 마친 뒤 기능 개발을 진행하며, 화면에 없는 기능을 임의로 추가하지 않는다.
- 작업은 탭, 기능 또는 인프라처럼 독립적으로 검증할 수 있는 단위로 나눈다.
- 제품 구조나 디자인 방향을 크게 바꾸는 결정은 선택지와 이유를 먼저 제시하고 확인받는다.
- 명확하게 요청받은 범위 안의 구현과 안전한 검증은 별도 확인 없이 진행한다.
- 단계가 끝나면 완료 내용, 검증 결과, 다음 단계와 남은 위험을 알린다.
- 완료는 코드 작성이 아니라 타입 검사와 실제 iOS 화면·동작 검수까지 포함한다.

## 2. Git과 공개 저장소

- 의미 있는 기능, 탭 개편, 디자인 실험, 환경 변경은 각각 독립 커밋으로 남긴다.
- 서로 다른 목적의 변경이나 기능 구현과 리팩터링을 한 커밋에 섞지 않는다.
- 사소한 중간 수정까지 기계적으로 커밋하지 않는다.
- 커밋 후 해시와 `git revert <hash>` 형태의 복구 방법을 제공한다.
- 사용자가 요청한 경우에만 원격 저장소에 푸시한다.
- 앱 UI, 더미 데이터, 문서와 로그에 사용자의 실명·토큰·비밀값을 넣지 않는다.
- 공개 전 변경 파일과 민감정보 포함 여부를 확인한다.

## 3. Daymo의 제품 정체성

- Daymo는 함께 여행 후보를 모으고 일정·장소·준비·요리·기록을 관리하는 여행 수첩이다.
- 핵심 가치는 `빠른 진입`, `함께 관리`, `많아져도 한눈에 보임`, `여행 후에도 간직함`이다.
- 연인뿐 아니라 친구·가족 등 여러 공간과 여러 멤버를 지원한다.
- 기본 색상은 `Daymo` 로즈베리 테마이며 사용자가 정해진 테마 조합을 선택할 수 있다.
- 다크 모드는 시스템 설정을 따르거나 사용자가 직접 선택할 수 있다.

## 4. 시각 디자인

- 여행 수첩, 종이, 테이프, 스크랩의 감성은 정보 구조를 돕는 범위에서 사용한다.
- 전형적인 AI 스타일의 반복적인 둥근 카드, 과한 그라데이션과 불필요한 배너를 피한다.
- 의미 없는 아이콘, 이모지와 장식용 일러스트를 넣지 않는다.
- 한 화면의 색은 역할에 맞게 제한하고 배경색이 제각각 보이지 않게 한다.
- 아기자기함은 작은 비대칭, 절제된 색 포인트, 질감과 정교한 간격으로 표현한다.
- 라이트·다크 모드에서 문구, 섹션, 테두리와 상태 색의 대비를 모두 확인한다.

## 5. 화면 밀도와 글자

- 첫 화면에는 사용자가 바로 확인하거나 실행할 핵심 정보만 둔다.
- 목록과 카드 높이를 작게 유지하고 불필요한 스크롤을 만들지 않는다.
- 데이터가 많아지면 접기, 더 보기, 그룹, 태그와 필터를 사용한다.
- 빈 공간을 채우기 위해 중복 정보나 작동하지 않는 장식을 추가하지 않는다.
- 제목은 보통 18pt 이상, 본문·입력값은 13~17pt, 보조 정보는 11~12pt를 기준으로 한다.
- 중요 정보와 조작 문구에 9pt 글자를 사용하지 않는다.
- 작은 시각 버튼은 `hitSlop`으로 충분한 터치 영역을 확보한다.
- 시스템 큰 글자에서도 잘림을 확인하며 확대를 일괄 제한하지 않는다.
- `react-native-safe-area-context`를 사용하고 하단 탭이나 상태 표시줄과 콘텐츠가 겹치지 않게 한다.

## 6. 공통 입력과 상태 변경

- 추가·수정 화면은 제목, 설명, 필드, 추천 선택, 완료 동작의 구조를 통일한다.
- 필수와 선택 항목을 명확히 구분하고 핵심 입력을 먼저 배치한다.
- 태그는 직접 입력과 추천 태그 터치 선택을 함께 지원한다.
- 입력이 많으면 관련 필드를 한 행이나 의미 단위로 묶는다.
- 완료 버튼은 입력 가능 여부와 실행 결과를 명확히 표현한다.
- 생성 후에는 사용자가 시작한 버튼이 의미하는 탭이나 목록으로 이동한다.
- 수정과 삭제를 제공하되 삭제는 주 동작보다 약하게 표현하고 확인 절차를 둔다.
- 멤버 내보내기, 공간 나가기, 로그아웃, 계정 삭제도 영향을 설명하고 확인받는다.

## 7. 탭별 핵심 규칙

### 홈

- 다음 여행, 숙소와 일정·장소·준비 바로가기를 우선한다.
- 바로가기는 해당 화면을 직접 열어야 하며 여행 첫 화면으로 돌아가면 안 된다.
- 체크리스트에는 지금 해야 할 행동만 보여주고 지난 여행은 기록으로 연결한다.
- 다음 여행이 없으면 새 여행 생성 동선을 제공한다.

### 여행 목록·지도·캘린더

- 동일한 여행을 목록, 대한민국 지도와 캘린더로 확인할 수 있어야 한다.
- 지도는 핀치, 버튼, 마우스 드래그와 휠 입력을 고려하며 확대 기준점이 예측 가능해야 한다.
- 확대·축소 반복 시 지역 위치가 틀어지지 않아야 하고 지역 선택 결과를 바로 보여준다.
- 행정 경계는 중복되거나 외곽선과 어긋나지 않아야 한다.
- 초기 지도는 가볍게 표시하고 상세 경계는 확대 수준에 따라 나눠 불러온다.
- 캘린더의 여행 기간은 날짜 사이가 이어져 보이며 빈 마지막 주 공간을 만들지 않는다.
- 여행 생성의 지역과 기간 선택은 긴 가로 스크롤에 의존하지 않는다.

### 여행 상세·일정·교통·숙소

- 탭은 여행, 장소, 준비, 조건부 요리, 기록으로 구성한다.
- 일정이 길면 전체 보기와 접기를 제공하고 `일정에 담기`는 실제 일정에 반영한다.
- 교통편은 가는 편·오는 편을 전환하며 출발/도착 장소와 시간을 대응 구조로 보여준다.
- 가는 편 저장 뒤 오는 편 등록 여부를 물을 수 있다.
- 숙소는 체크인·체크아웃을 편하게 입력할 수 있어야 한다.
- 여행 메모는 상단에서 확인하며 추가·수정·삭제를 지원한다.

### 장소

- 여행 후보 장소를 수집하고 결정하기 위한 독립 관리 탭으로 유지한다.
- 태그를 핵심 관리 수단으로 사용하고 카드 내부 태그에는 구분되는 배경을 둔다.
- 카드 높이를 작게 유지하고 의미 없는 아이콘을 넣지 않는다.
- 태그가 많아지면 더 보기나 별도 관리 화면을 사용한다.
- 네이버 지도 링크는 선택 사항이다.
- 네이버 지도 공유 텍스트를 붙여 넣으면 이름·주소·링크를 자동 채운다.
- 사용자가 명시적으로 숙소로 등록한 장소만 숙소로 취급한다.
- 사용처가 없는 태그는 자동 정리하거나 관리 화면에서 제거할 수 있게 한다.

### 준비

- 검색보다 담당, 상태와 태그 기반 관리에 집중한다.
- 개인별 준비물과 공용 준비물을 구분한다.
- 필터는 전체, 남은 준비, 완료처럼 상태 중심으로 제공한다.
- 담당 선택에는 실제 공간 멤버의 가명을 사용하고 공용을 함께 제공한다.
- `내가 챙길게` 대신 `담당 변경`을 사용한다.
- 행 전체를 눌러 완료 상태를 바꾸고 체크 표시는 상태를 보조한다.
- 많은 항목을 기준으로 그룹, 접기, 더 보기와 진행 상황을 제공한다.
- 목록 복사·붙여넣기는 하단 관리 도구로 두고 요리 재료를 불러올 수 있게 한다.
- 실제 알고리즘이 없는 추천을 개인화 기능처럼 표현하지 않는다.

### 요리

- 숙소에 주방이 있을 때 표시하며 여행 설정에서 탭을 켜거나 숨길 수 있다.
- 여러 요리와 재료를 추가·수정·삭제할 수 있어야 한다.
- 요리별 재료와 전체 장보기 목록을 구분하며 내가 준비할 재료를 모아 본다.
- 재료 분류는 사용자가 만들거나 선택할 수 있다.
- `담당`보다 `준비 방법`을 사용하고 가져가기·구매 등 행동 기준으로 표현한다.
- 레시피와 유튜브 링크를 저장하고 바로 열 수 있어야 한다.
- GPT용 고정 형식 프롬프트와 일괄 붙여넣기는 미리보기와 확인 뒤 반영한다.

### 기록과 메모

- 여행 메모는 여행 상세 상단, 사진·일기·여행 카드는 기록 탭에 둔다.
- 사진과 일기는 추가·수정·삭제를 지원한다.
- 사진으로 보관 가능한 여행 결과물을 만들 수 있어야 한다.
- 콘텐츠가 적을 때 억지로 섹션을 늘리지 않고 명확한 빈 상태를 제공한다.

### 우리·인증·그룹

- 이메일 인증과 OAuth를 고려하고 소셜 로그인은 이메일 입력 아래에 둔다.
- 로그인 화면 아이콘은 실제 Daymo 앱 아이콘과 일치한다.
- 여러 그룹을 즉시 전환하고 그룹별 데이터를 분리한다.
- 더미 멤버는 실명이 아닌 가명을 사용한다.
- 멤버별 권한과 담당을 표시하고 위험 동작에는 확인 창을 제공한다.

## 8. 로컬 우선 데이터와 성능

- 앱 실행과 재진입 속도를 최우선 품질 기준으로 둔다.
- 첫 화면을 위해 전체 서버 응답을 기다리지 않고 로컬 데이터로 먼저 그린다.
- 테마, 화면 설정, 최근 검색, 초안과 캐시는 기기에 저장한다.
- 여행, 일정, 장소, 공용 준비물, 담당 상태와 공유 메모는 서버를 공동 기준으로 둔다.
- 오프라인 변경은 작업 큐에 저장하고 백그라운드에서 동기화한다.
- 사진은 크기 조절과 썸네일을 사용하고 원본 업로드 정책을 별도로 둔다.
- 지도와 대형 데이터는 단계적으로 로드한다.
- 백엔드는 Java 중심으로 ConoHa VPS 3 Core, RAM 2GB, SSD 100GB에서 동작하도록 설계한다.
- 트래픽 무제한과 별개로 CPU, 메모리, 저장 공간과 외부 API 비용을 관리한다.

## 9. 개인정보와 출시

- 이용약관, 개인정보 처리방침과 선택적 마케팅 동의를 구분한다.
- 개인정보의 항목, 목적, 보관 기간과 삭제 방법을 고지한다.
- 위치, 사진과 알림 권한은 해당 기능을 사용할 때 이유를 먼저 설명한 뒤 요청한다.
- 앱 안에서 계정 탈퇴와 데이터 삭제 경로를 제공한다.
- 소셜 로그인 제공사와 앱스토어 정책을 확인한다.
- 오픈소스 라이선스, 문의 경로, 이용약관과 개인정보 처리방침을 제공한다.
- 출시 전 관련 법률과 정책은 최신 공식 자료 및 전문가 기준으로 재검토한다.
