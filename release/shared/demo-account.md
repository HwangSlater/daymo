# 데모 계정

App Store·Google Play 심사자에게 건넬 로그인 계정이다. 서버 작업 `app.jobs.seed_demo`(backend/app/jobs/seed_demo.py)가
계정과 예시 내용을 만들고, 다시 돌리면 처음 상태로 되돌린다.

## 만들기와 되돌리기

VPS에서 운영자가 돌린다. 떠 있는 api와 같은 이미지로 한 번 실행하고 컨테이너를 지운다(정리 작업 `daymo-cleanup`과 같은 방식).

```sh
# 비밀번호를 화면에 보이지 않게 입력받아 이 셸에만 둔다. 명령행 인자로 넘기지 않는다(셸 기록·ps 에 남는다).
read -rs DEMO_PASSWORD && export DEMO_PASSWORD

docker compose --env-file /etc/daymo/secrets/runtime.env \
  -f /srv/daymo/current/backend/infra/production/compose.yml \
  run --rm --no-deps -T -e DEMO_PASSWORD api \
  python -m app.jobs.seed_demo --email review@daymo.xyz

unset DEMO_PASSWORD
```

- `-e DEMO_PASSWORD` 는 값 없이 이름만 적는다. 호스트 셸의 값을 컨테이너로 넘기고 명령에는 값이 남지 않는다.
- `--password-file <경로>` 도 받지만 컨테이너 안의 경로여야 한다. 운영 compose는 비밀 파일을 api에 마운트하지 않으므로 환경 변수를 쓴다.
- 비밀번호는 가입과 같은 규칙(8자 이상, 흔한 값 불가)을 따르고 DB에는 Argon2id 해시만 남는다. 작업은 비밀번호를 찍지 않는다.
- 이메일은 실제로 받을 수 있는 주소여야 한다(`support@daymo.xyz` 별칭 권장, [../README.md](../README.md) "정할 것"). `.test`·`.invalid` 같은
  예약 도메인은 앱 로그인 화면의 이메일 검사에서 막힌다.
- 끝나면 `데모 계정 새로 만듦: 공간 1개, 여행 3개, 사진 5장`(두 번째부터는 `다시 채움`) 한 줄을 남기고 0으로 끝난다.

**언제 다시 돌리나.** 심사를 내기 직전에 돌린다. 날짜가 실행한 날 기준이라, 오래 두면 "다가오는 여행"이 지난 여행이 된다.
심사자가 내용을 지우거나 계정 삭제를 눌렀어도 다시 돌리면 돌아온다. 비밀번호를 바꾸면 그 계정으로 로그인해 있던 기기는 끊긴다.
심사자가 비밀번호를 여러 번 틀려 로그인이 잠시 막혔으면 그것도 풀린다.

## 다른 계정은 건드리지 않는다

표시 칼럼 없이 이렇게 알아본다. 아니면 **아무것도 바꾸지 않고** `데모 계정을 만들지 않았다: …` 를 남기고 1로 끝난다.

1. 그 이메일로 계정이 없으면 새로 만든다.
2. 있으면, 그 계정이 가진 공간 중에 데모 멤버(`demo-yeoul@example.com`, `demo-garam@example.com`)가 들어 있는 공간이 있어야 한다.
   example.com은 메일을 받을 수 없는 예약 도메인이라 그 주소로는 이메일 확인을 끝낼 수 없고, 확인하지 않은 계정은 초대를
   받을 수 없다. 그래서 이 작업 말고는 그런 공간이 생기지 않는다.
3. 그리고 그 계정이 들어가 있는(나간 것 포함) 모든 공간에 본인과 데모 멤버 말고 다른 사람이 없어야 한다.
4. 누가 데모 멤버 주소로 가입해 비밀번호나 소셜 로그인을 붙여 두었으면 그 계정은 가져다 쓰지 않고 멈춘다.

다시 채울 때는 그 계정의 공간을 `purge_space` 로 통째로 지우고(사진 파일 포함) 새로 만든다.

## 심사자가 보는 것

이름은 모두 프로젝트의 예시 이름이고 사진은 사람이 없는 단색 그라데이션이다. 장소는 실제 관광지 이름을 쓴다.

- **계정:** 이름 "하늘", 이메일 확인이 끝났고 지금 판의 약관 동의가 기록된 상태
- **공간:** "주말 여행 메이트"(친구) — 하늘(관리자), 여울·가람(편집 가능)
- **여행 3개** (날짜는 실행한 날 기준)

| 여행 | 날짜 | 상태 | 들어 있는 것 |
