# 스크린샷

두 스토어 모두 **실제 앱 화면**이어야 한다. 웹 빌드 캡처나 목업으로 기능을 부풀리지 않는다.
데모 계정(예시 이름·예시 여행)으로 찍는다. 실제 사람 이름·연락처·사진이 보이면 안 된다.

## 규격

| 스토어 | 크기 | 장수 | 비고 |
| --- | --- | --- | --- |
| App Store | 6.9형 iPhone 세로 1320×2868 또는 1290×2796 | 3~10장(최소 1장) | 6.9형을 올리면 작은 화면은 줄여 쓴다. iPhone 16/17 Pro Max급 기기나 시뮬레이터에서 찍는다 |
| Google Play | 세로, 각 변 320~3840px, 긴 변이 짧은 변의 2배를 넘지 않게 (예: 1080×1920) | 2~8장 | 요즘 폰 화면(1080×2400 등)은 2배를 넘으니 위아래를 잘라 1080×1920으로 맞춘다. 제출 전 콘솔 규격을 다시 확인한다 |
| Google Play 그래픽 이미지 | 1024×500 | 1장 | `release/assets/play-feature-graphic.png` |

## 찍을 화면과 순서

여덟 장을 이 차례로 찍는다. 첫 장이 스토어 목록에 제일 크게 걸리므로 홈이 맨 앞이다.
캡션은 이미지 위에 얹는다(`release/scripts` 밖, 작업용 스크립트가 만든다).

| # | 화면 | 어떻게 가는지 | 캡션 (큰 줄 / 작은 줄) |
| --- | --- | --- | --- |
| 1 | 홈 | 로그인 직후 | 다음 여행이 한 장에 / 숙소·일정·준비물·쓴 돈까지 한눈에 |
| 2 | 여행 → 일정 | 홈에서 여행 카드 → 「일정」 탭 | 일정과 교통편을 날짜별로 / 가는 편, 숙소, 예약까지 한자리에 |
| 3 | 여행 → 준비 | 준비 탭 | 누가 무엇을 챙길지 나눠요 / 같은 걸 둘이 챙기는 일이 없게 |
| 4 | 여행 → 요리 | 요리 탭 | 해 먹을 요리와 장볼 것까지 / 현지에서 살 것과 집에서 챙길 것 |
| 5 | 여행 → 비용 | 비용 탭 | 누가 누구에게 얼마를 보낼지 / 나 기준으로 정산을 정리해요 |
| 6 | 여행 → 기록 | 기록 탭 | 사진과 일기로 오래 남겨요 / 여행이 끝나도 지우지 않아요 |
| 7 | 추억 카드 | 기록 탭 → 필터 「카드」 → 카드 한 장 누르기(크게 보는 화면) | 여행을 한 장으로 만들어요 / 사진을 골라 네컷으로 꾸미기 |
| 8 | 우리 → 멤버 | 아래 띠 「우리」 → 「함께하는 멤버」의 관리 | 링크 하나로 함께 시작해요 / 받은 사람은 바로 참여해요 |

App Store에는 이 중 1·2·3·5·6·7 여섯 장을 쓴다.

### 화면에 보여야 하는 것

빈 목록이 찍히면 그 탭이 무엇을 하는 곳인지 드러나지 않는다. 데모 계정(`app/jobs/seed_demo.py`)은 이 조건을 만족하도록 채워 둔다.

- **준비**: 준비물이 여러 개이고 **일부만 체크**돼 있어야 한다. 전부 체크하면 「남은 준비」가 빈 화면이 된다.
- **기록**: 사진이 격자를 채울 만큼 있어야 한다. 씨앗이 만드는 단색 사진은 스토어에 쓰지 않는다.
- **추억 카드**: 카드가 미리 만들어져 있어야 한다. 씨앗은 카드를 만들지 않는다. 기록 탭의 필터가 「카드」일 때 격자에 카드만 남는다.
- **일정**: 교통편이 가는 편·오는 편 두 장 다 보이면 좋다. 카드는 편마다 한 장이다.
- **비용**: 정산에 「누가 누구에게」 한 줄이 보여야 한다.

## 먼저 웹으로 구도만 본다

기기로 찍기 전에 같은 여덟 화면을 웹에서 찍어 **구도와 캡션만** 확인한다. 스토어에 올리는 것은 늘 기기에서 찍은 것이다.

```sh
# 작업용 스크립트(세션 임시 폴더). 운영 주소를 그대로 찍는다 — 로컬 서버는 API 가 CORS 로 막혀 못 쓴다.
python store_shots.py                      # store-raw/ 에 여덟 장
python store_compose.py store-raw store-out  # 캡션을 얹어 1080x1920 으로
```

가장자리가 조금 잘리는 것은 웹에서 스크롤 위치를 맞추는 한계라 기기에서는 문제가 되지 않는다. 여기서 볼 것은
**여덟 장이 한 벌로 읽히는지, 캡션이 화면과 맞는지** 둘뿐이다.

## 찍는 법

- iPhone: TestFlight 빌드를 실제 기기에 설치 → 측면 버튼 + 볼륨 올리기. Pro Max가 없으면 Xcode 시뮬레이터(iPhone 17 Pro Max)에서 ⌘S.
- Android: 내부 테스트 빌드 설치 → 전원 + 볼륨 내리기. 또는 `adb exec-out screencap -p > shot.png`.
- 상태 표시줄의 시간·배터리는 깔끔한 상태로(시뮬레이터: `xcrun simctl status_bar booted override --time 9:41`).
- 찍은 원본은 `release/screenshots/app-store/`, `release/screenshots/play-store/` 에 번호 순서로 둔다.

### 찍기 전에

1. 데모 계정으로 로그인한다(`shared/demo-account.md`). 실제 계정으로 찍지 않는다 — 진짜 이름과 사진이 스토어에 올라간다.
2. **밝은 모드**로 맞춘다. 여덟 장이 같은 모드여야 한 벌로 보인다.
3. 알림 배너가 뜨지 않게 방해 금지를 켠다. 찍는 도중 배너가 지나가면 그 장은 버린다.
4. 키보드가 올라와 있지 않은지, 새로고침 표시가 돌고 있지 않은지 본다.

### 찍은 다음

캡션을 얹고 1080×1920으로 맞추는 일은 스크립트가 한다. 찍은 파일 이름을 `01-홈.png` 처럼 번호로 시작하게 두면
번호로 캡션을 찾는다. Play는 위아래를 잘라 1080×1920으로, App Store는 자르지 않고 1290×2796 그대로 올린다.
